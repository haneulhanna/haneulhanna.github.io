# Editorial plan — final portfolio

## Strongest overall technical story
Hanna is strongest when presented as a low-level computer engineer who can move between firmware, real-time systems, RTL/digital hardware, Embedded Linux, and physical-system debugging. The portfolio should show a coherent progression across those layers rather than a long list of classes and small labs.

## Ideal order
1. Concise identity / technical focus
2. Experience summary — Qidni, DF/Net, UWASIC
3. Four flagship case studies
   - Qidni embedded control + diagnostics
   - Qidni Embedded Linux platform + provisioning
   - ECE 350 RTOS kernel
   - UWASIC TinyTracer ALU, with ECE 327 as related RTL breadth
4. Supporting projects
   - STM32 water reservoir
   - multithreaded crawler
   - audio/FATFS system
   - ECE 380 motor/control work
5. Compact technical breadth
   - ECE 318 communications
   - ECE 222 RISC-V/computer architecture
   - DF/Net production C++
6. Education / skills / contact

## Keep as flagship
- Qidni motor/valve diagnostics + stall investigation
- Qidni Embedded Linux / provisioning
- ECE 350 Real-Time Executive
- UWASIC TinyTracer ALU

## Reduce
- ECE 327: strong, but supporting UWASIC avoids two separate RTL sections with overlapping proof.
- Water reservoir: medium project with useful physical-system breadth.
- DF/Net: professional and important, but not a flagship for an embedded/RTL-first general portfolio.
- ECE 380: supporting controls/hardware breadth.
- C crawler / audio system: compact supporting evidence for concurrency and embedded data paths.

## Remove from the general portfolio
- First-year alarm prototype
- traffic-light FSM
- generic ECE 318 / ECE 380 photo galleries
- digital timer PCB
- market-data pipeline
- graph project
- automated scraping project
- WAT.ai
These are real, but they either duplicate stronger proof, dilute the low-level identity, or are better reserved for role-specific versions.

## Visual strategy
Use only a small number of real images:
- Qidni bench debugging / waveform
- Linux architecture
- STM32 reservoir
- controls lab
Everything else uses simple block diagrams or text. No decorative animations, quotes, manifesto, or oversized editorial copy.
